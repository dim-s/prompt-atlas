# Vendor / model differences — the matrix

The single source of truth for **how models differ** along behavioral axes that affect prompt wording. Each row is a model. Each column is an axis. Cells encode the model's bias along that axis.

When reviewing a prompt:
1. Identify the target model(s).
2. Read the relevant rows here.
3. Drill into `models/<vendor>.md` and `agentic-systems/<system>.md` ONLY for nuance the matrix can't capture.

When adding a new model: add a row here first. If a row needs more than 1-2 sentences per cell, push the detail into `models/<vendor>.md` and keep the matrix terse.

---

## How to read a cell

- **Numerical scale** (literalism, persona-tolerance, etc.): `low / medium / high` — model's bias along that axis. Higher = more of that property.
- **Recommendation scale** (few-shot, emphasis, etc.): `helps / neutral / hurts` — what adding this technique does on this model.
- **Mechanism column** (reasoning lever, output format): names the actual API knob or technique that works best.
- **Migration column**: how to port a prompt from the previous version.
- **Default column**: what the model does without explicit guidance.

When a cell says `?` — the axis hasn't been tested for this model; treat conservatively (see Universal-prompt rules in `principles.md`).

**Reading guide:**
- *"hurts"* = adding this technique measurably degrades output on this model.
- *"overtriggers"* = the model applies the rule beyond intended scope; use sparingly.
- *"strip persona"* = "You are an expert at X" lines should be removed; outcome-first beats persona.
- *"+5% boost"* = Google reports identity-based prompting ("You are a planner") boosts reasoning on Gemini 3 by ~5%. **Opposite default to GPT** (`gpt.md` rule #12); documented for Gemini 3, not restated for Argon — flag in cross-vendor reviews.
- *"distillation identity confusion"* (GLM) = the model occasionally responds "I am Claude, created by Anthropic" — a documented training artifact. Persona blocks that hard-pin identity may misfire; functional-role wording is safer.
- *"DeepSeek user-prompt priority"* = V4 practitioner guidance (citing R1-era vendor advice; no current DeepSeek page states it) puts **core instructions in the user message**, with a brief system prompt ("You are a senior architect" style). Opposite default to most other vendors; flag when porting Claude/GPT system prompts to V4 — but as a "measure this" flag, not a rewrite order: the rule has failed to reproduce twice on V4-Flash-0731, now archived (`models/deepseek.md § Family-wide rules #1`, field notes 2026-08-19 and 2026-08-21, the latter a Claude-authored agent body running verbatim as V4-Flash's system prompt).
- *"over-prescriptive skills degrade output"* (Fable 5) = Anthropic's prompting guide is explicit: skills and prompts developed for prior models are often too prescriptive for Fable 5 and can degrade quality. Review and trim before adding; brief instructions outperform behavior-by-behavior enumeration.
- *"Opus 5 over-verifies"* = Anthropic's guide is explicit that Opus 5 checks its own work unprompted, and that verification instructions carried over from earlier models compound with that behavior — costing tokens with no quality gain. The documented fix is **removal**, not softening. This inverts `techniques.md §20`, which stays correct for every other Claude.
- *"Opus 5 also widens scope"* = unlike 4.7/4.8, which only failed to generalize *downward* (missing items you didn't enumerate), Opus 5 can add steps you didn't request. Narrow tasks need both boundaries stated, not just the lower one.
- *"restating an instruction is measured cost"* (GPT-5.6) = OpenAI's latest-model guide reports leaner system prompts scoring ~10–15% higher on evals while using 41–66% fewer tokens. Duplicated instructions, verbose tool descriptions and belt-and-braces repetition are the named targets; state each rule once.
- *"carried-over 'be brief' overcorrects"* (GPT-5.6, Gemini 3.6 Flash) = both models are terser by default than the version they replace, so a concision instruction written for the older one now stacks on an already-short default. **Opus 5 points the other way** (runs long, doesn't calibrate, `effort` won't shorten it) — this is a live cross-vendor contradiction, so express length as a task requirement ("at most 5 bullets"), not as a disposition.
- *"vendor-designated subagent model"* (Gemini 3.5 Flash-Lite) = Google's changelog positions it as *"a low-latency, highly cost-effective subagent option designed for high-volume automation"* — the first model in this atlas named for the role. Same prompting regime as any cheap executor: explicit success criteria, named tools, tight scope, schema-driven output.
- *"no prompting guide published"* (Grok 4.x — xAI has no text-model guide, Gemini 4 Argon, Mistral Medium 3.5, Muse Wonder / Spark 1.3 / 1.2, Tencent Hy4 preview, MiniMax M3.1-Flash, Xiaomi MiMo-V2.6, StepFun Step 5 Preview — `models/other-frontier.md`) = the vendor documented the model but not how to prompt it. Muse Spark Open and Glimmer do have guides; Muse Code is an agent, not a model. Cells inherit the family default; don't manufacture a version-specific delta that no source supports.
- *"asks focused questions when the answer could change the outcome"* (GPT-6 Astra) and *"asks clarifying questions when prompts are ambiguous"* (Muse Spark 1.3) = two vendors shipped a collaborator default in the same week. Interactive agents gain; non-interactive runs stall on questions and confirmation pauses. OpenAI publishes initiative snippets (`models/gpt.md § GPT-6 Astra`); Meta publishes no control (`models/meta.md § Muse Spark 1.3` — test). Either way, state what is already authorized and what to do on ambiguity.
- *"3.8 Flash works harder"* (Gemini 3.8 Flash) = extra reasoning steps and iterative tool calls by design, with more tokens at higher effort. Reverses the 3.6 / 3.7 terseness noted above: don't port persistence scaffolding, and treat efficiency as lower effort (3.7 Flash now routes to 3.8 Flash), not as a "be brief" line.
- *"Sonnet 5 moved to Opus-level literalism"* = prompts written assuming Sonnet 4.6's looser generalization now under-apply — state scope explicitly. Sonnet 5.5 keeps that baseline.
- *"ask it to think less doesn't work"* (Sonnet 5.5, Haiku 5.5) = both guides say a system-prompt line asking for less thinking or a direct answer did not reduce thinking in Anthropic's tests. The lever is the effort level; strip such lines.

**Cross-vendor rule for reasoning depth:** never write "think harder" or "think step by step" in the body. The lever is the API parameter on all current vendors (Claude `effort`, OpenAI `reasoning_effort` / `reasoning.effort`, Gemini `thinking_level`, Kimi `reasoning_effort` on K3 / K3.1 Pro and the `thinking` toggle on K2.6 (retiring), GLM-5.3/5.2 `reasoning_effort` (5.3: no off-switch), Qwen `reasoning_effort` + `enable_thinking` on 3.8 (Max, Flash), DeepSeek `thinking` toggle + effort (low/high/max since 2026-08-13; open weights 1–100), Grok `reasoning_effort` since 4.5 (4.3 also accepts `none`), Mistral `reasoning_effort` (Small 4 / Medium 3.5 / Large 4), Meta `reasoning_effort` / `reasoning.effort` (hosted) and `reasoning_effort` / `reasoning_strength` (open weights), Tencent Hy4 `high`/`no_think`, MiniMax `effort` (no off-switch), MiMo `thinking.type`, StepFun `reasoning_effort`). The one documented prose-level control is Muse Spark Open's `Reasoning strength: N.` system-prompt line (`models/meta.md § Muse Spark Open`) — valid for that model only. Wording substitutes: "Verify against criteria...", "List edge cases first...".

**The mirror rule, now with a hard case:** never write "don't reason / answer immediately" either. It's inert prose on every vendor, actively harmful on Opus 5 with thinking disabled (leaks internal tags — `antipatterns.md` #38), and **structurally unimplementable where thinking is forced on**: Kimi K2.7-Code / K3 / K3.1 Pro, **GLM-5.3** (all variants), **Grok 4.5 / 4.6 / 4.7**, **Claude Opus 5.5** and **Sonnet 5.5** (lowest is `between_tools`), **Mistral Large 4**, **hosted Muse (Wonder / Spark — `none` → 400) and Muse Spark Open**, **MiniMax M3.1-Flash**, **StepFun Step 5 Preview** (no off-switch documented), and the **Qwen3.8-Max open weights (`Qwen3.8-2.4T-A95B`)**. Even where an off-switch exists (Haiku 5.5, Grok 4.3, GPT-6.1 Terra), it is a parameter, not a sentence. Latency complaints are an effort setting or a model choice, never a sentence in the prompt.

**Gemini-specific gotcha:** `thinking_level` and legacy `thinking_budget` cannot coexist in one request — returns 400 error. When migrating from 2.5 prompts, audit code for both.

**Sampling gotcha (now an industry trend, not a vendor quirk):** on **Gemini**, `temperature` / `top_p` / `top_k` were deprecated on 2026-07-21; the current prompt-design page: *"Gemini 4 and Gemini 3.6+ models ignore custom values for `temperature`, `top_p`, and `top_k` and return deprecation warning headers (and will return `400` errors in a future release)… For earlier Gemini 3 models, keep these parameters at their default values"*. On **Claude**, API version `2026-10-21` rejects `temperature` / `top_p` / `top_k` at any value on every model (`models/claude.md` § sampling). **GPT-6 Astra and GPT-6.1 Sol never take sampling parameters** (no `none` effort, and the guide drops `temperature` / `top_p` / `top_logprobs` whenever effort isn't `none`); **GPT-6.1 Terra, GPT-6 Sol and GPT-6 Luna take them only at effort `none`**. GPT-5.6 is not covered by that rule. **Kimi** fixes sampling on the hosted API; **Grok** reasoning models error on `presencePenalty` / `frequencyPenalty` / `stop`.

Most frontier vendors have now removed or pinned the lever within a year, in the same direction: **tone and variety are a wording problem, not a sampling problem.** Cross-vendor wording: don't reference sampling in the prompt body, and don't design a prompt whose variety depends on it. For design/creative variety, use "propose N directions, then implement the chosen one" — the replacement pattern that works everywhere.

**Kimi sampling is fixed on the hosted API:** temperature 1.0 and top_p 0.95 on K3 / K3.1 Pro / K2.7-Code; K2.6 fixes temperature by mode (1.0 thinking / 0.6 Instant) and top_p at 0.95. Any other value returns an error. The model cards' top_p 1.0 values (K2.6 Thinking, K3 agentic) apply only to self-hosting. Never put sampling in a Kimi prompt body.

**DeepSeek-specific multi-turn gotcha:** with tools, the `reasoning_content` field **must be round-tripped** on every later turn or the API returns 400; without tools it is ignored and dropped. V3.2 / R1 **rejected** the field (archive). Let the client library handle it.

**GLM-specific system-prompt gotcha:** Z.ai's GLM models have thinking enabled by default but **heavy system prompts (especially Claude Code's) suppress the reasoning judgment**, and the model rarely engages chain-of-thought under that load. **On GLM-5.3 / 5.3-Flash / FlashX (`low`/`high`/`max`) and GLM-5.2 (`high`/`max`) the first mitigation is the `reasoning_effort` param** — set it out-of-band. Where a router doesn't forward it (or on the archived GLM-5.1 and earlier), cross-tool routers work around this by injecting custom `<reasoning_content>` markers and instructing the model to "write detailed reasoning before answering" — not by removing the host system prompt. Treat heavy persistent-context files as actively hostile to GLM thinking unless mitigations are present.

## How to use the matrix during a review

### Step 1 — Pick rows

- Single-model prompt → 1 row
- Universal-Claude → all current Claude rows (Fable 5.1, Opus 5.5, Sonnet 5.5, Haiku 5.5, plus the previous Fable 5 / Opus 5 / Sonnet 5 if still in use); intersect (write for the strictest). Legacy Claude rows are in `archive/matrix-legacy.md`. **Caution:** several axes point in opposite directions inside the family — self-review vs task checks, subagent delegation, narration, the thinking off-switch. Intersecting them mechanically produces a prompt that's wrong for half the set; use the conditional phrasings in `models/claude.md § Universal` rule 7
- Universal-GPT-5.x → all GPT-5.x rows; intersect
- Cross-vendor → strictest cells across both vendors

### Step 2 — Pick relevant axes

- Behavior of the prompt under review tells you which axes matter:
  - Is it a long persistent-context file? → table E
  - Does it prescribe step-by-step? → table A column "Step-by-step prescription"
  - Does it use a persona ("You are...")? → table A column "Persona"
  - Does it specify output format in prose? → table B column "Output format"
  - Does it use few-shot examples? → table A columns "Few-shot..."
  - Does it use aggressive emphasis? → table A column "Aggressive emphasis"
  - Does it tell the model to "think harder"? → table B column "Reasoning depth lever"
  - Does it spawn subagents? → table C column "Subagent default"

### Step 3 — Compare the cell to what the prompt does

- If the prompt does the thing the cell calls "neutral / helps" → no finding.
- If the prompt does the thing the cell calls "hurts / overtriggers / strip / fresh baseline" → `[IMPROVE]` or `[CRITICAL]` finding.
- If the prompt skips a technique the cell says "needed" → `[ADD]` finding.

### Step 4 — Cite the matrix in the review

When proposing a change, say *which row × column* drove it. Example: *"Persona line 'You are a senior engineer' → strip on GPT-5.6 (table A, column 'Persona/act-as' = hurts)."* This makes the recommendation auditable and the user can challenge it from the matrix instead of from your authority.

## Adding a new model — checklist

When extending the skill to cover a new model (e.g., a new Gemini, DeepSeek or Grok release):

- [ ] Add a row to **all five tables** (A through E). Use `?` for unknowns; `?` is honest, guesses are dangerous.
- [ ] **Where rows are per-model (A, B): add a separate row. Where the family is merged into one row (C–E, and B for e.g. 'DeepSeek V4-Pro / Flash'): join the family row unless the new version has a documented behavioral difference** — separate rows for undocumented deltas are fabrication. A brand-new family (e.g. Tencent Hunyuan) gets its own row in all five tables.
- [ ] Add a `models/<vendor>.md` file ONLY if the new model has nuance the matrix can't capture in 1-2 sentences per cell.
- [ ] If the new model runs in a new agentic system, add `agentic-systems/<system>.md` with system-specific quirks (file paths, hierarchy, hooks, headless mode).
- [ ] Update `models/_universal.md` if the new model changes the cross-vendor compromise (e.g., a third vendor with opposite defaults to both Claude and GPT).
- [ ] Add its row to `references/lineup.md` and, if the vendor published a delta list, a checklist to `references/model-audits.md`.
- [ ] Move the model it makes two-generations-stale (or the vendor retired) to `references/archive/` — rows to `archive/matrix-legacy.md`, sections to `archive/models/<vendor>.md` (policy: `archive/README.md`).
- [ ] Don't add new principles to `principles.md` unless the new model invalidates a universal — that's a much bigger event than adding a row.
